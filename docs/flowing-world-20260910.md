# 持续世界、信息衰退与重复提醒检查

版本：0.16.79。状态的生成与衰退在每次读取新的上一轮正文时共同进行。新事可以在旧事未结束时开始，各人物和组织在同一段已过剧情时间内并行活动。AI根据当时的可行条件选择延续、新行动或停顿；空栏检查是兜底，不是新活动的唯一入口，也没有每轮强制新增或结束一条的配额。

## 逐项检查

| 栏目 | 每轮可能发生的变化 | 保留与退出依据 |
| --- | --- | --- |
| NPC活动轨迹 | 场内外各人物延续行动、开始新行动、被打断或完成；不同人物并行 | 保留当前活动与尚未结束部分，不能把新活动当成所有旧事务都结束。场外推演保留依据与推测标记 |
| 人物概况 | 位置、处境、当前目标随行动改变 | 身份、性格、能力等稳定设定不因没提到而丢失；新位置不能来自未来目的地 |
| 组织/势力 | 各方行动、资源、目标和关系变化 | 按参与者、行动、资源和结果更新，不随每次读取凭空升级冲突 |
| 日程、主角任务 | 新安排、改期、取消、新的可选目标、已接受任务进展 | 可以同时有多件事项；到期不等于完成；候选目标不等于玩家接受；新事项不覆盖其他未兑现承诺 |
| 触发器、长期线程、剧情推进 | 新机会与前提、多个未决线索、阶段与决策点变化 | 条件不成熟就等待；成熟只是具备资格；已经消耗的同一次事件不能换措辞复活 |
| 世界进程、因果影响 | 多个参与者驱动的变化、传播、持续后果、修复、补偿、减弱与转化 | 原因消失可能开始减弱，余波仍在就保留；减弱不等于消失。结束需要实际依据或明确的推演记录，不因读取次数变多自动结束 |
| 资源/约束、人物关系 | 消耗与补充、恢复、权限变化、实际互动造成的关系变化 | 必须有世界内原因，不能凭空生成硬禁令、数值或固定关系结局 |
| 世界状态、地图 | 当前时刻、环境、位置、探索与道路通行情况 | 当前快照更新；地理结构与其他仍有效的信息保留，旧时间不能和新时间持续并存 |
| 硬规则、事实锚点、知识/秘密 | 规则有实际变化才更新；认知随目击、告知或传播更新 | 不按热度删除，不能把AI知道当成人物知道，也不能因时间过去自动解除秘密边界 |
| 时间线、世界书补充 | 保存实际历史和独有背景；按关联召回 | 历史不能通过推测伪造；原文备份保留，已完成读取的无关背景不逐轮全部注入 |

慢速/极慢模式控制前台叙述焦点与时间跨度，各人物并行活动仍使用同一段剧情时间，不能因此额外跳过一段时间。读取同一正文不能重新随机改写已建立活动或不断顺延日期。

## 已修复的具体问题

1. 原先一条提醒只记最后一次发送原因，主动查询可能覆盖到期原因。现在保留各类发送原因；用户查询、相关提及时若已经到期，也记下该次到期提醒。
2. `before`替换后的新句继承提醒历史，正文生成回执在结算后提交的路径也补做继承。可唯一定位的同名事项手工替换同样继承；新日期仍有自己的到期提醒。
3. 相同主体和标签值、只是标签顺序不同，不新增副本或无意义版本；否定、例外、不同事实不做模糊合并。
4. 同一未变未来事项不会因连续相关输入反复主动提醒，明确询问仍可召回；触发条件实际变化后仍可产生新提醒。
5. 状态读取明确每轮检查并行演化，空栏补全不再被解释成必须先清空旧事；前台变化点限制不再暗示所有后台人物串行。
6. 因果影响、世界进程等也进入本地核验上下文。可解析的消退/结束条件提供满足、受阻或待核实结果，但不把“可以消退”直接当成“已经消失”。
7. 明确结束的推测活动可以退出活跃集合，归档保留推测性质，不能变成确认历史或用于证明事件已发生。剧情推进的结束状态同样可以归档。
8. 世界当前时间等明确单一快照在有唯一、完整新记录时取代旧值；原文历史仍留在本地。世界书主体名直接匹配补足分词器无法识别的虚构名词。

## 是否还会越堆越多

必须区分本地记录、状态读取上下文和正文注入：真实发生的历史、独有知识及未结束的并行事务可以合理增长，不用固定条数或轮数强行删掉。结束/替换项退出活跃集合，旧结果只在本次退出、当前事项关联或用户查询时进入读取上下文；完整本地历史可供回顾与依赖核验。无变化的重复保存不会添加新的历史条目。

正文注入按当前规则、约束、知识边界、人物和场景相关性选择。仍相关的事实可以持续存在于上下文，但这不要求正文每轮重新叙述；未来提醒另外去重。没有采用固定六轮删除或降温。长期有效事实、真实历史和持续增加的真实事务仍会使本地存档增长，当前没有承诺无限聊天下存档或所有模型输入恒定大小。

任意自然语言同义改写不能全部由本地代码可靠识别。普通读取要求同事实复述KEEP，语义合并交由AI；精确替换和明确的结构等价由代码保证。完全换主体标题、换日期或把同一内容跨栏当作新增，仍需要模型正确判断，不能声称彻底杜绝所有重复。

## 验证范围

`smoke-flowing-world.mjs`验证并行新增、保留未结束事项、空栏兜底、因果减弱、推测记录退出、80轮无变化稳定性、提醒去重、改写、改期、序列化、相关召回和提示规则。`smoke-plain-memory.mjs`通过真实Engine、API封装、SSE解析和保存流程验证非空栏新增与结算改写后的提醒继承，初始化仍最多两次、后续一次。

另有日期/权限/因果条件、人物知识边界、世界书合并读取、世界书注入、状态视图、投递、回滚及聊天隔离回归。没有调用真实付费模型，也没有直接修改用户聊天事实；这验证程序机制，不替代对真实模型推演质量的长期观察。刷新插件后，下一次正文读取会带上新的演化规则。
