# v0.16.76：句子记忆、世界书承接与完整回传

所有栏目遵循客观记录：具体行为、原话、条件、权限、时间和已发生结果优先，避免强化性、绝对化或宿命化标签。来源明确的意图保持说话者归属；必要推测保留依据与不确定性，不能变成因果事实或强制结局。人物情绪不是世界进程；因果影响只能记录已出现的影响或有可观察变化支撑的形成过程。全栏目必填不授权虚构心理、因果和剧情。

初始化、推演、正文更新和整理均须复核旧memory，按来源用before修正旧标签及错误解释。正文注入（包括手动结论覆盖和世界书补充）带一份固定的状态使用约束，不逐轮叠加：性格不自动推出行动，旧推测不作为必达目标，无新证据不加重表现，不替玩家决定感受和关系结局。原始设定与确实发生的限制行为保留；没有做无来源的关键词批量替换。该措施约束模型写法与使用方式，不声称代码能独立判断所有心理描写的真实性。

知识/秘密以角色的信息缺口为重点：不知情者及具体未知部分、只知部分、误解、怀疑、实际知情者与获知条件。认知边界随完整信息持续回传（尊重明确的模块关闭设置），不是发过一次就消耗的提醒；否定句“没有人知道某事”属于有效信息。面板优先展示不知情与不完整认知。新增获取只能根据明确渠道或带依据的推测；未记录知情者不等于证明其余所有人不知情，也不能把作者/AI知道当作人物知道。读取、推演、补读、整理均检查这些边界，仍不增加模型调用次数。

世界书补充优先采用可逐字还原的规则简写：复用重复规则或长前提，严格保留内容及原文顺序；发送前核对展开结果与原文完全一致，不能缩短时仍用原文。原文保存和状态归栏保持原有职责，详见 [规则简写与验证](worldbook-compression-20260910.md)。

世界书不再依赖酒馆原书持续启用：原文随当前聊天保存并用于后续分析；本轮状态未完整覆盖的部分保底回传。规则、人物、关系、世界观和其他重要背景仍要求实际归入栏目。KEEP 是不输出更新的操作说明，不是记录，旧的独立 KEEP 会被剔除且不能通过全栏目完成校验。详见 [世界书承接与验证](worldbook-takeover-20260910.md)。

本版本已接通 `index.js → state-logic.js / plain-memory.js → API句子解析 → Storage → UI/Injection/Engine`。新增时钟、明确条件验算、安全清理和原文历史召回，详见 [实现与验证](state-logic-20260910.md)。相关内容完整回传，不按字符预算或每栏条数截断。

## 存储

人物栏目中的一条记录直接是：

```json
{"memory":{"characters":["张三现在住在京城"]}}
```

事实内部不保存 ID、引用、来源、类型、优先级、活跃度或更新时间。栏目就是归属，不保存另一份结构化事实副本。聊天级读取位置、版本、锁、回滚快照和用于去重投递的短键仍由程序管理，不交给模型生成。历史快照为回滚而保留，不能把单条事实的缩减比例理解成整个聊天文件的缩减比例。

旧记录自动本地转换。已有单句原样保存；复杂旧记录把事实、否定、条件、例外、关系方向和知识边界转成文本，已知引用转为人物/地点名称。不会把“所在地”擅自改成“居住地”；缺少名称的旧引用保留“原记录指定但未命名的对象”，不带原始 ID。复杂旧档案可能仍较长，新模型更新将按句子精简。

## 初始化固定两阶段

v0.16.68 起，“读取当前聊天”只在首次或明确清空读取后开放；初始化开始即保存本聊天的使用标记，已有内容、成功或失败后均不能叠加初始化。运行中仍可终止。清空的是插件状态，不是原始聊天消息；日常用“读取上一轮正文”增量更新，用一次 API 智能整理处理冗余。

1. 第一次读取角色卡、世界书、Persona、聊天资料，保存必要的既有设定与当前事实，不同时要求长篇审计或世界模拟。
2. 第二次取得原始资料与第一阶段已存句子，复核并填写全部栏目；先读取世界书和上下文，再依据设定推演缺项。NPC轨迹根据人物职责、性格、能力、时间、位置和既有安排推演，场外推测保留标记与前提。最多三条后台判断保存在后台栏目，同时带明确AI判断标签回传正文。

推演必须服从既有规则和因果，不能改写已确认历史、替用户做决定或让角色无渠道获知秘密。未直接描写的场外活动可按可靠前提推演，不能因为未直接写出就留空；根据已有设定及因果推演缺项并标注推测，不用未知或暂无占位。

每阶段完成的合法句子立即保存并可在面板查看。第一阶段截断时，第二阶段利用原资料与已有内容补齐；第二阶段失败保留第一阶段内容。存在无效替换或没有完整结束回执时标记未完成，不自动追加第三次调用。所有栏目必须有内容，且在生命周期清理后仍需非空才能标记完成；不能把已有一条内容误当成没有漏项。

## 后续一次合并更新

正文生成前只注入已存状态，不额外调用状态 API。正文完成后一次请求同时：结算 user/assistant 实际变化、补齐栏目、推进 NPC 自主活动及世界状态、返回简短判断。请求包含当前句子、本轮正文、角色卡、世界书及配置范围的上下文；有空栏或原初始化未完成时读取完整可用上下文补漏，不按来源字符预算截断。稳定事实与仅被复述的安排保持不变。

模型传输只需要 JSONL：

```jsonl
{"module":"characters","before":"张三现在住在京城","text":"张三已搬到杭州"}
{"module":"npcActivities","text":"张三正在杭州新居整理行李。"}
{"module":"planner","text":"张三仍需取得通行许可才能进入内院。"}
{"end":true}
```

`before` 仅是本次精确替换定位，不存进事实。不存在的旧句不会被模糊猜测匹配。新增只传 `module/text`。尾部截断只保留闭合的完整句子，不能从坏行中捡出嵌套假记录；解析也容忍完整 `records` 外壳，并剥除偶发多余字段。截断/失败不会自动重试扣费，未完成不会冒充已读完。同一正文的部分结果重试共用最初的回滚点。

## 注入与界面

AI 与编辑框仍使用一行一条短文本；展示由 `memory-view.js` 在本地投影，不存第二套状态，不发排版请求。地图呈现可折叠的包含层级与当前位置；人物按主体合并展示身份、位置和状态；关系分方向显示箭头；组织以各方势力为主体；知识区分知情与不知情；任务显示目标、进展与完成条件；日程和历史分时序展示；因果与世界进程显示路径链。其他栏目保留对应的规则、约束、线程和判断卡片。

有主体时可写“张三｜身份：守卫｜位置：京城 > 城门｜状态：负伤”；地图用“国家 > 城市 > 建筑 > 房间”，关系用“张三 → 李四｜态度：信任但仍有戒备”。这些仍是 `text` 字符串，不要求固定完整表或额外管理字段。旧句保留原文，明确的名称、位置和关系方向可被本地识别；无法确定的内容完整展示，不猜测组织、层级、数值或关系。旧人物归属不会伪装成势力概况，缺失内容在后续基于资料的读取中补齐。

地图在与当前场景/输入相关时发送，历史在明确回顾时召回。世界规则、资源约束、命中的秘密和其他相关记录完整保留，不截断条件或例外。本地日期、权限与条件核验随原文回传，并在卡片显示。UI投影不会改变注入、提醒状态或回滚快照。

未来任务/日程/下一步按相关输入、主动查询或明确时间触发；同一未变化的到期事项投递后保持安静，主动询问可再次召回。本轮后台判断传给正文，明确不能覆盖当前事实与本地受阻结论。普通事实按当前输入、场景与在场人物选择，新必要状态首次完整传递；预览不消耗投递次数，成功结算后才记录。句子模式不按热度删事实。

时间只使用剧情日期。支持公历与24小时时分、“昭国四年秋第十七日”及有锚点的“三日后”“明天18:00”等。重复读取不顺延，旧无锚点相对时间不使用当前或电脑日期。日期精度不冒充已知时辰，年号跨年跨季未给历法时保持待核实。到期不等于完成。

## 使用与验证

刷新酒馆加载 v0.16.71。已有状态保留，无需清空；后续正文读取优先提取明确限制、位置与活动，修正玩家/NPC目标归属并检查场外人物。先读实际移动和场景，缺失时延续上次位置；都未说明时才按职责、行踪、距离和时间推断合理范围，并标明“推测”，不把目的地或回忆当当前位置。本次改造前的备份位于 `_backups/0.16.69-before-state-logic`。

未完成原因包括结束标记缺失、旧句替换/锁定校验错误，并输出不含正文的初始化校验日志。空栏目明确列入未完成原因，即使响应有end也不算完整；后续正文补读可读取原始资料补齐，完成后解除未完成标记。旧版“等待完整结束回执”没有保留具体原因，不能倒推出该轮错误。

`node dev/smoke-plain-memory.mjs` 使用模拟 HTTP 提供方，实际经过 Api.complete、SSE解析、句子解析、Engine公开入口、保存与界面渲染，验证初始化2次、后续1次、全栏目填写、NPC生成、旧数据迁移、精确替换、截断、失败、晚到响应、回滚、聊天隔离和提醒去重。样例记录从184字节降到26字节。独立浏览器预览也验证了人物栏目编辑保存后的真实显示。未用真实付费模型评测推演质量。
# 智能整理（v0.16.67）

“整理状态 → 智能整理”使用独立的 1 次 API 预算，发送当前完整记忆、锁定栏目及原始资料，合并重分类时必须保持所有栏目有内容。模型合并语义重复、整理主体概况、纠正栏目归属，并清理已有明确新状态取代的旧状态。保留不同事实、条件、例外、知识边界、重要历史和未完成事项，不通过整理推进剧情或假造遗漏事实。

输出继续使用 `module/text/before` 差量，跨栏移动同时删除原条并新增目标条。收到完整结束回执且每条改动通过校验后统一保存，自动保留整理前快照；截断、错误旧句或锁定冲突均不部分写入、不自动重试。界面显示实际变化的栏目与条数；无变化则显示“无需调整”，不生成空版本。整理保持读取楼层、轮次与初始化完成标记不变。

### v0.16.69 地点补全
每次正文结算在同一次 API 中检查已有的人物概况与活动记录，位置缺失视为需要更新，不仅检查空栏目。优先正文和已有位置，缺失时再按设定推断并标明。活动责任范围与人物实际所在地分别判断；界面可直接识别旧活动短句中明确的地点，不将未来计划、否定或回忆认作当前活动地点。
