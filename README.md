# 芝芝状态机系统（SillyTavern 扩展）

## 0.16.91：两次调用内分批保存与定点接续

初始化仍严格串行、最多2次API。流式响应每形成一批可校验的完整JSONL记录就排队写入本地状态，不等待整段响应结束；断流、超时或尾部截断只舍弃未闭合的末条，已经保存的记录保持可见并标记为未完成。流中的本地保存不调用API，也不会并发写状态。

第二次调用固定作为定点接续：携带第一步已保存的memory、缺失栏目和具体校验问题，优先补缺与纠错，不重抄正确内容，并要求逐条短输出以降低单次输出负担。超时、网络断流和输出残缺可由既定第二步承接；401/403、密钥、权限、参数、额度等终止类错误立即停止，不浪费第二次调用。诊断区分流式中断、格式或残缺尾部、缺少end:true和栏目缺项；接口stop仍不等于完整成功。

## 0.16.90：首正文之前保留完整等待窗口

修复仅收到少量推理后，60秒停流规则抢先中断首正文等待的问题。第一条正文到达前只执行首正文上限（最多180秒）和总时限；收到正文后才启用60秒无新增正文或推理的停流规则。推理和心跳都不能延长首正文或总时限，初始化单次总上限仍为300秒。进度提示显示当前适用的等待规则，未取得完整JSONL记录时明确保留此前已保存内容。

此修复避免提前取消，不保证上游一定返回正文；不会新增重试或API调用，也不会把接口的stop当作有效end:true。初始化第一步允许暂空无依据的栏目，第二步继续核对补全。刷新加载新版，无需清空记忆；已有未完成读取可用“读取上一轮正文”继续补全。

## 0.16.89：插件始终可读选中原书，首轮提取、次轮推理

修复已读回执把世界书从插件请求中移除的问题。首次读取、第二步推理及后续读取都携带当前全部选中条目的完整原文，同时保留角色卡、Persona与正文。已读标记只用于显示处理状态，不再代替原书；旧非空选择中未曾出现的新挂载或新开启条目默认跟随原开关，明确取消仍有效。

首次读取自动拆解全部选中世界书，只整理来源明确给出的内容，不为填满栏目提前推演。能自然归栏的内容进入对应栏目，其余独有信息压缩到世界书补充；第二步结合原书与已保存栏目核对、纠错及推理补全。提示词要求保留条件、否定、例外、数量、时间与关系方向，合并重复而不删独有信息，不要求逐条展示证据链。代码不截断选中原文，模型压缩的语义完整性仍需核对。

正文AI继续接收栏目与压缩补充，不注入接管条目的原文。默认选择挂载书中的开启条目，可在设置中增减，无需先点单独拆解。初始化最多两次API；读取诊断新增输入世界书条数与字数。刷新加载新版，无需清空已有记忆。此前版本说明中“已读后只传压缩结果”的行为由本版替代。

## 0.16.88：恢复挂载世界书与逐条拆解选择

修复旧设置启用选择过滤、但 entryKeys 为空时把挂载书全部过滤成0条的问题。旧空列表恢复为“当前挂载且启用的条目”；新版明确取消全部条目时仍保持全不选。非空旧选择继续生效，切换角色不会因历史选择自动带入上一张卡的书。

设置新增“世界书”页，世界书补充页也有“选择世界书 / 拆解条目”入口。默认跟随当前角色、聊天、Persona、全局挂载和条目开关；可逐本/逐条取消，手动加入关闭条目，也可从酒馆世界书列表中额外选择未挂载书。选择立即保存，不调用AI、不改动原书；恢复默认会清除手动覆盖与额外选择。新版手动选择优先于原条目开关，未手动覆盖的条目继续跟随原开关。

“立即拆解已选条目”使用1次API，可取消；正常初始化仍最多2次，普通更新仍1次。完整设定按现有语义压缩逻辑进入关键栏目和世界书补充。取消选择停止后续拆解，已经归栏的记忆不自动删除。已接管数表示保存的原文备份，选择页另列当前挂载与参与拆解数。刷新加载新版，无需清空记忆。

## 0.16.87：流式卡住的等待上限与实时进度

修复推理包或空 choices 包反复重置整段等待时间的问题。独立 API 与酒馆转发流式请求现在分别限制首条正文等待（最多180秒）、收到有效内容后的连续停流（最多60秒）及单次总时长（沿用任务上限，短句记忆为300秒）。推理可以刷新停流计时，但不能延长首正文或总时限；空包、角色包和心跳不续时。底层 fetch/read 即使没有响应取消，也会由本地等待保护退出并释放任务。

进度每秒更新等待秒数、正文/推理字数与无新增内容时间，同一步更新不会挤掉此前步骤。诊断增加实时计数、最近数据/内容到达时间及 timeoutKind（first_text/idle/total）。超时只接收已有完整记录并标记未完成；用户取消直接退出。未新增重试或 API 调用，已有状态保留，刷新酒馆加载新版，无需清空记忆。此修复限制本地等待，不能消除上游网络错误或保证模型响应速度。

## 0.16.86：语义压缩、重要内容归栏与补充再压缩

世界书先拆成 AI 可理解的简洁逻辑，再按重要性与当前用途分配：关键规则、身份、状态与约束归入对应栏目；其余有价值的次要细节、低频设定留在“世界书补充”，即使它们可以归类为人物或地图，也不全部塞进常驻栏目。第二步继续合并压缩补充、删除与关键栏目的重复，并完成状态推演。条件、否定、例外、因果、时间与知识边界保留；不设置字数、条数或压缩比例，不按固定长度截断。

原文只交给尚未完成的拆解请求。拆解完成后，第二步与后续状态请求使用已保存的压缩结果，不再重复携带未改动的原书；改动条目单独重新拆解。正文原文兜底已移除，接管条目的酒馆原生注入也被拦截，包括未完整拆解时；原文件不改写，面板中的原文仅作本地折叠备份。正文使用关键栏目与压缩补充。

更新并刷新后，旧版仅“已读取”的条目会在下一次读取或智能整理时按新压缩规则处理一次；已有过长内容由 AI 用 before 合并替换。无需清空记忆。初始化仍最多两次调用，普通更新/整理仍一次；当前挂载、勾选与启用过滤规则保留。压缩质量取决于模型执行，代码不以固定缩短比例判成功。

## 0.16.85：无需控制台的读取诊断

进度下方展开“读取诊断”，可复制当前页面最近 6 次请求的输入/输出字数、首包及首个文字等待时间、总耗时、结束状态和本地校验计数。卡慢期间也能复制；浏览器禁止剪贴板时可手动复制文本。不记录密钥、模型名称、接口地址、聊天原文或原始报错，不写入记忆、不增加 AI 请求；刷新后重新记录。缺失指标显示 null，推理字符仅统计接口公开返回的部分。

“未完整确认”提示改为明确说明本次读取已结束、有待修正项，避免误以为还在等待。此版本提供线上耗时排查信息，未改变两次初始化、提示词或栏目校验规则，不能据此宣称已修复线上延迟。

## 0.16.84：世界书按当前挂载与条目开关读取

只读取当前角色绑定及酒馆明确启用的全局、聊天、Persona 世界书；历史勾选、上次读取记录和角色卡内嵌旧副本不再恢复另一张卡的书。关闭的条目不进入读取或原文补充；整本关闭视为空书，不回退旧缓存。已有插件条目选择模式开启时，仍须同时勾选条目；切换角色和读取不会改写这些勾选记录。普通模式沿用酒馆原生条目开关。

本次读取用当前有效来源替换原文缓存；正文生成时也用酒馆当前条目过滤原文补充。读取失败只报告当前挂载的书，不恢复旧书、不新增 API 请求。更新后刷新酒馆生效。之前已经混入人物、规则等栏目的旧句子不会自动删除，因为旧句子没有逐条来源记录；可在相应栏目删除误混内容。

## 0.16.83：修复流式接收的重复解析开销

修复 0.16.82 的结束检测在收到小数据块时反复解析累计响应的问题。现在增量处理 SSE 和句子边界，仅遇到完整结束回执时核对全部内容；进度界面最多每 250 毫秒刷新一次。保留断流保护、结束回执校验与原有 API 次数。新增 1000/2000 个流式包的处理量测试，验证解析工作随数据量近似线性增长；这不代表不同设备或网络的实际耗时相同。

## 0.16.82：流式结束与连接错误

读取短句时，收到通过完整性校验的 `end:true` 即结束接收，不再等待代理关闭连接；空心跳不再重置无有效数据的等待期限。`Load failed` 等连接错误改为明确提示并保留已有状态。半途断流仍只接收完整句子，不标记本次已完整读取，不增加自动重试或 API 调用。

更新扩展后刷新酒馆。已有句子无需清空；初始化不完整时，可用“读取上一轮正文”携带完整来源继续补全。真实网络、服务器或 API 中断仍需排查对应连接；本版本改善接收与提示，不能保证所有网络请求成功。

## 0.16.81：剧情扣子显示简化

剧情扣子的条件、影响和状态分行显示，详细条件核验默认折叠；仅检查已写出的前提，不再为缺省字段重复显示“待核实”。发送给 AI 的核验文字同步精简，保留明确受阻原因与“条件满足不等于已发生”的约束。已有安排保留原日期位置，移除“日期未锚定，需核实原约定时间，不能以重读日期顺延”提示。

安装：在 SillyTavern 的扩展管理中选择安装扩展，填写 `https://github.com/lunanaya/ZZ-zhuangtaiji`。升级后刷新页面，已有记忆无需清空。

## 0.16.79：持续世界演化与提醒去重

每次读取新正文，AI按同一段剧情时间检查各人物、组织、活动、事务和因果影响的并行变化。旧事未结束、栏目未清空也可产生有依据的新活动；空栏补全保留为兜底。衰退按实际时间、进展、资源、条件与因果判断，不按读取轮数删除状态。慢速模式限制前台叙述焦点，不让全世界排队行动。

到期、相关提醒和主动查询分别保留发送历史，查询不会重置到期提醒；明确替换及可唯一识别的同名事项改写继承提醒记录，真正改期仍可再提醒。标签顺序变化不新增副本，世界书背景按当前输入或场景召回；已归档结果按当前关联提供给状态读取。初始化仍最多两次API，后续读取仍一次。刷新加载此版本，已有记忆无需清空。

各栏目检查、边界和回归结果见 [持续世界与信息衰退](docs/flowing-world-20260910.md)。

## 0.16.78：世界书合并为两步读取

“读取当前聊天”固定最多两次 API：第一步完整读取当前启用/绑定的世界书、角色卡、Persona及所选范围的正文，直接按原有短句格式归栏；第二步结合完整原始资料与第一步结果，补充遗漏并推理当前状态。第一步只提取事实，正文已确立的变化优先于初始状态；不追加第三步，不显示单独读取的付费选项，也不增加引用或覆盖报告。

地图、人物（包括次要人物）、硬规则、组织、关系等进入对应栏目；只有无法归类的背景简写留在“世界书补充”，该栏允许为空。原文折叠保留作为备份，成功读取后不再整段回传。失败/截断保留已返回的完整句子并提示未完成，不自动追加请求。原有正文更新、条件判断与回滚逻辑保留。旧聊天可沿用“读取上一轮正文”或“整理状态”合并读取世界书，无需为了升级清空记忆。

独立“拆解世界书”设置页、顶部按钮和酒馆世界书编辑器旁的一键按钮已移除。“世界书补充注入位置”移到设置 → 注入模块，可选角色定义前/后、作者注释前/后，默认角色定义之后；作者注释本轮未启用时落到角色定义之后。归栏内容沿用原栏目注入位置。下文为历史版本说明，旧版独立拆解和原文保底行为以本节为准。

**v0.16.76：全栏目客观记录与防止标签加码。** 新增、更新、整理和本轮判断统一采用具体行为、原话、权限、条件及已发生结果，避免强化性人格标签、主观根因和预设关系结局。旧条目也按原始资料复核，不能因未变就保留错误解释。正文回传加入固定的状态使用边界：不把性格与既有记忆当作每轮加重表现的指令；无新证据保持当前尺度，不替玩家决定感受和选择。真实限制行为不被温和词掩盖，世界书原文不篡改。刷新后约束生效，旧记录可用读取上一轮正文或智能整理按资料修正，不用清空。

**v0.16.75：知识/秘密优先维护不知情边界。** 读取时逐条检查char与相关NPC不知道什么、只知道哪部分、误解或怀疑什么及获知条件；不得把AI读过世界书视为角色知情。面板把不知情/部分知情/误解放在知情者前，完整知识边界持续回传，不因发送过或关键词没命中消失。“没有人知道……”不再被过滤为空记录。没有新获知证据就保持边界；缺少资料不等于能凭空断言所有人不知情。刷新后用“读取上一轮正文”补齐旧档，不用清空。

**v0.16.74：世界书补充优先使用校验过的规则简写。** 将重复的完整规则或长前提定义一次，再按原文顺序引用；代码逐字展开核对，必须与原文完全一致、且算上说明后确实更短，才能用于正文回传。条件、否定、例外、次数、顺序和知识边界全部保留，不能验证或无法缩短时用原文。“世界书承接”可对照精简回传与完整原文。已接管内容刷新后自动生效，不增加 API 调用。详见 [规则简写与验证](docs/worldbook-compression-20260910.md)。

**v0.16.73：世界书承接与 KEEP 修复。** 读取时要求规则、人物设定和世界观充分融入对应栏目；已接管原文随聊天保存，原世界书关闭后仍供状态分析与正文 AI 使用。本轮未完整逐字覆盖的原文保底回传，不按关键词或字符预算丢弃。“世界书 → 世界书承接”可查看全部接管原文。独立拆解也会保存原文并接通正文注入。KEEP 只表示不修改旧内容，不能保存成记录或算作填满栏目。刷新后用“读取上一轮正文”补读，已有记忆无需清空。详见 [承接规则与验证](docs/worldbook-takeover-20260910.md)。

**v0.16.72：修复清空读取的确认入口。** 清空改用插件内可见的确认窗口，不再依赖可能被内嵌浏览器抑制的原生确认框。取消或 Esc 保留记忆；重复点击只处理一次，确认期间切换聊天或开始读取会中止清空。刷新酒馆后生效，保留 v0.16.71 的全栏目必填与完整回传规则。

**v0.16.71：恢复全栏目必填。** 修正v0.16.70错误引入的“允许空栏”：所有栏目先读世界书/角色卡/上下文，再按设定推演缺项并标明推测，不能用未知或暂无占位。正文更新与智能整理均带原始资料；存在空栏或初始化未完成时，正文补读读取完整可用上下文。完成校验在生命周期清理后执行，空栏不能显示成功，整理不能把最后一条删空。保留已有时钟、条件校验与完整相关回传；仍为初始化最多2次、正文更新1次、整理1次API。刷新后可用“读取上一轮正文”补齐已有记忆，无需清空。

**v0.16.70：剧情时钟、条件验算、状态生命周期与完整回传。** 句子模式取消字符预算和每栏5条截断；本地检查权限、明确数值资源、前置条件、到场、时间及已知路线，结论随相关原文回传正文AI。日程首次锚定，重读不顺延；已结束事项退出活跃状态，先回传结束结果并保留可召回历史。玩家任务需明确接受，场外活动保留推测及前提。仍使用 `module/text/before`，初始化最多2次API、正文后1次、智能整理1次，本地计算0次。刷新酒馆加载，已有记忆无需清空；旧正文的漏提取在下一次正文读取中修正。以 [当前句子存储说明](docs/plain-memory.md) 和 [实现与验证记录](docs/state-logic-20260910.md) 为准。

这是一个把“世界模拟”和“正文写作”分开的 SillyTavern 前端扩展。Planner API 维护持久世界状态并给出本轮约束；它既可直接跟随酒馆当前 API，也可使用单独的 OpenAI 兼容接口。正文完成后，Planner 再进行一次事实结算，只有真正写进正文的事情才成为历史。

v0.16.53 保持初次读取的“事实提取 + 独立推演”两次 API 逻辑，但压缩了移动端反代的单次输入与输出。流式结束标记缺失或输出触及上限时，会先在本地只保留已闭合的 JSON 模块，不再把已完成证据整批丢弃。

## 历史结构化版本说明（v0.16.62 及更早）

- 读取当前角色卡、Persona、聊天以及能够从 SillyTavern 上下文解析到的已启用世界书。
- 普通轮次只读取可见的近期 user/assistant 正文。只有用户手动执行完整校准时，才会把酒馆中 `is_system=true` 的历史归档楼层连同可见正文一起纳入；这些隐藏原文不会在之后每轮重新展开。
- 普通轮次在正文生成前只注入最近一次成功状态，不调用或等待状态 API；正文完成后用 1 次后台 API 读取最新正文并更新状态。重 roll 会先回滚旧候选的状态，再读取当前候选。中间的正文模型是 SillyTavern 自己的生成请求。手动完整读取严格只用 2 次插件 API：请求 A 一次性提取聊天、角色卡、Persona与世界书的全部栏目，请求 B 基于 A 的结构化事实独立推演。A 的完整模块会立即留存，不用第三次请求掩盖输出截断。
- 上一轮正文的增量结算使用提示词约束 JSON 并在本地严格校验，不向 Gemini/兼容网关发送复杂 `json_schema`，避免后端编译约束时出现 `too many states for serving` 的 400，也减少请求启动等待。
- 正文后请求保留全部非空状态栏目、卡片、事实依据和来源引用，但不发送空字段与运行诊断；返回中的智能引号、尾逗号和正文内未转义引号会在本地保守修复，不增加 API 次数。
- GPT-5 / o 系列会自动使用兼容的输出参数与低推理强度。受调用上限保护的请求只尝试一次结构化 JSON；若上游超时、返回空内容或无效 JSON，会保留旧状态并显示错误，不再切换模式追加第二次扣费。
- 初始化时面板会显示“读取资料 → 处理世界书 → 等待模型”三阶段进度、实际读取条数及失败详情；状态机面板不会再遮挡酒馆自带的确认或 API 错误弹窗。
- 读取/初始化按字符将角色卡、Persona、世界书与完整聊天切成有界块；聊天块相邻保留 2 层重叠。每块只输出带 `factId` 和 `sourceRefs` 的状态变化、冲突与逐楼层处理结果，不生成剧情摘要。全部变化按时间重放后建立分界点基准快照，早期块不会在一次最终大合并中被挤掉。
- 每个成功块立即写入当前聊天的 `chatMetadata.worldStateMachine.historyMemory`。模型只返回变化、冲突和确实无法读取的楼层；完整块内其余楼层由本地程序确定性标记为已检查，避免逐楼层回执造成输出爆炸。任一块失败会记录明确失败状态并保留旧世界状态，本次操作不会偷偷切换线路或重试；再次读取时复用前面成功且字节未变化的块，只把确切失败块确定性拆半后续读。
- 后端转发使用 SillyTavern 官方 `getRequestHeaders()` 取得当前 CSRF 令牌；“使用酒馆默认 API”开关切换后立即保存，关闭设置窗口时不会出现界面已勾选、实际仍走自定义 API 的状态错位。
- 世界书是唯一设定来源。每条已选原文按段落建立覆盖表和约 800–1200 字语义块，生成稳定 `factId`、唯一 `owner`、`delivery`、适用范围、来源与依赖；精确原文另行完整保留，不以摘要替换，也不做首尾截断。缓存按条目内容哈希失效，只重建变化的条目。全量事实/静态地图目录无 200 条容量上限；每轮相关性筛选才最多处理 200 条候选，且完全在本地完成。
- 设置中的“分解正文”和“拆解世界书”是两个独立页面：前者控制普通轮次与“全量提取→独立推演”的两次读取，后者只管理世界书条目、缓存和本地逐轮路由。
- 正文注入不再共用单一深度：当前反馈与 Planner 位于深度 0，世界与人物快照位于 1，地图/关系/知识位于 2，任务/事件/因果位于 3，长期后台项目位于 4；拆解后的世界书规则沿用对应原条目的世界书深度。
- “系统 → 输入来源”显示最近一次推演真正读取到的世界书名称、启用条目数、正文条数、角色卡与 Persona 状态；发现但读取失败的世界书会单独列出。
- “系统 → 最终注入”直接预览下一次真正按深度发送给正文模型的统一载荷，不再另拼一份世界书提示。最终汇编器以 `factId` 去重并解析依赖；事实只由 `owner` 输出，owner 模块关闭时才回退到世界书模块。硬规则的正文、条件和例外作为不可分割单元保留。点击小铅笔可临时修改完整文本，覆盖只用于下一次生成，结算后自动恢复动态组合。
- 顶部“世界书注入”与“世界、人物、事务、系统”并列；每个已拆解条目显示其段落覆盖、语义块和事实目录，并保留兼容的核心规则、触发情境、条件规则和必要背景编辑入口。修改后下一轮会重新筛选并由统一汇编器注入。
- “环境与路人反应”可在注入模块中单独开关。公共场景里由正文动作自然触发的轻量反应（如飞机乘客回头看一眼）可以出现，但临时路人不会被写进持久 NPC、关系或长期事件。
- 第一次运行建立完整状态；此后使用同一份状态增量演化，不逐轮重建。
- 每轮正文生成前只在本地读取最近一次已结算状态并生成短注入；正文完成后用唯一一次 Planner 请求检查全部栏目。无变化默认 `KEEP` 并省略，已有对象使用 `UPDATE/REPLACE/MERGE`，只有独立新对象才能 `CREATE`。
- 顶部“整理状态 → 智能整理”调用一次 AI：合并同义记录和同一主体的散落概况，修正栏目归属与有明确依据的旧状态，保留条件、例外、秘密和未完成事项。仅传当前记忆并返回差量，不重发整段聊天、不推进剧情。完整校验后统一保存并建立整理前快照；无需调整时明确显示结论，不生成空 REV。失败不自动重试，运行中禁止重叠 API 任务。
- 设置新增默认关闭的“剧情节奏”。关闭时完全沿用正文模型原本节奏；开启后可选极慢、慢速、中速或快速，并分别控制是否允许自动切场景、自动时间跳跃。它只限制每轮最大推进幅度，不规划剧情、不提高事件强度，任何档位都必须停在用户决策点。
- 本轮推进依次执行剧情压力与空转侦测、角色行动与因果判断、后台事件队列、推进调度，但不新增四个设置项：行动与因果规则并入“因果影响”，其余三项并入“本轮后台判断”。它们复用现有状态ID，不复制事件数据；允许平静延续，不用突发事件填补冷场。
- NPC差异化调度：在场人物实时微观更新；离场人物按一小时后台间隔进行宏观更新；未到期则保持原状态。普通轮次的到期后台 tick 合并进正文后的唯一一次结算，只能沿既存动机、当前目标、日程、活动、任务、进程或因果推进，允许完全无变化。
- 人物概况只保存“是谁、在哪里、当前重要处境、持续状态、重要物品”。持续状态和重要物品只保留当前版本，并随恢复、治疗、遗失、转交、损毁或失去剧情价值自然更新和删除。
- NPC分为核心人物、活跃NPC和按需生成的背景NPC，并可按持续作用自然升降级。每个持久NPC只保存一条当前活动快照；背景NPC不长期占用状态。
- 场景地图分成无容量上限的世界书静态全图与运行时动态覆盖层；界面可切换“全部地图 / 玩家已知地图”。同名同父级节点合并，路线携带距离、预计耗时、开放/阻断状态、危险与权限规则引用，移动仍受现实路径约束。
- 人物关系保存并存关系类型、动态模式、双向或不对称视角、核心矛盾、依恋、未解决伤害、边界、和解条件与公开/私下/危险/政治冲突/脆弱时的差异表现，不使用亲密度等评分。爱不自动消除伤害，恨也不证明不爱；普通亲密、保护、坦白或争吵不会自动升级正式关系或完成和解。
- 知识以L1普通、L2重要、L3核心表示保留优先级，并以保密、受限、公开另行表示传播状态；重要性与公开状态互不替代。
- 每条运行记忆同时维护 `priority` 与 `activity`：L1/L2/L3决定能否淘汰，HOT/WARM/COLD决定本轮是否需要调用。正文新建或实际更新的条目自动升为HOT；长期未命中会由本地程序自然衰减到WARM、COLD。
- 最终注入只使用HOT以及少量与当前人物、地点或任务直接相关的WARM。L3+COLD仍保存在状态或原始世界书中，但不会仅因重要而每轮塞给正文模型；再次被当前正文或世界书路由命中后才升温。
- 集合模块允许为空，空表示当前没有值得进入运行态的信息；模型不得为了填满栏目制造NPC活动、任务、线程、事件或秘密，也不得用旧的模块文本填补空状态。时间、季节、地点、天气、环境等必填单值不会留空，而是明确显示“未明确”及其真实性状态。
- 空数组另有 `moduleCoverage` 标记，区分“有记录、只有覆盖检查、完整校准后确认无持久记录、空但未验证、读取失败、尚未检查”；面板和正文注入不会再把漏读或失败误认为“原文确实没有”。
- 所有持久条目统一维护 `truthStatus`、`basis`、`sourceRefs`：`confirmed`、`derived`、`system_generated`、`suspected`、`assumed`、`unknown`、`not_established`、`not_applicable`、`failed` 分别表示原文明示、确定推导、系统生成、证据推测、运行暂定、尚不清楚、尚未建立、不适用和读取失败。疑似/暂定内容不会自动升级为确认，L3核心信息不能由推测或系统生成创建。
- 推断权限按模块隔离：天气与一次性环境反应允许受约束生成；季节只有在日期和南北半球可确定时程序推导，衣着只作冷暖弱线索；人物身份、关系、秘密/知识、世界规则、任务、权限和命名地点没有来源时只能标为未知或尚未建立。系统生成的天气进入状态后必须连续演变，无来源的突变会被本地程序拦截。
- 所有状态遵守 `factId + owner` 单一主归属：现在能主动推进的是任务，等待条件的是可触发事件；一次条件节点是事件，长期未决故事是线程；围绕用户故事的是线程，世界自行变化的是进程；历史回顾进时间线，仍影响当前的重要节点进世界事件；当前结果进世界状态，来源与持续后果进因果影响；人物当前落点进概况，具体移动过程进NPC轨迹；怎么看对方进关系，知道什么进知识。消费者只保存稳定引用，不复制全文。
- 每次保存执行本地 `STATE_GC`：删除无价值终态、覆盖同对象旧版本、按权威键合并重复、把重要完成节点归档到时间线、压缩久远历史，并保护L3核心信息。L1临时状态在长期未更新后自动消费，L2只在活跃期间维护。
- 世界书、角色卡和Persona继续作为长期设定权威且原文始终保留；初始化只做检索、分级、去重、提炼和当前化，不再把两万字压成一份固定摘要，也不把完整世界观、生平和组织介绍复制进 `world.facts`。
- 时间线具有分辨率衰减：近期节点保持具体，超出容量的较早L1/L2记录会按阶段合并成摘要，L3历史不因容量自动删除。
- 世界状态只记录“现在是什么样”的当前快照；世界事件保存“发生了什么”的重要节点；世界进程只维护仍在演变的家族、组织、战争、公司权力、政策、舆论或大型环境变化线。
- “因果影响”保存既存事件或事实留下且仍在生效的后果。影响形成前为 `developing`，形成并持续生效后为 `active`，真正消失后才移除。
- 升级旧版后会自动迁移旧提示词并保留既有事实，同时标记需要刷新；点击一次“读取当前聊天”后，会从完整角色卡和世界书补齐事实所有权、硬规则、地图投影、关系/任务引用与NPC生活字段。不会在普通生成前静默发起重读；旧自定义提示词保存在 `promptMigrationBackup`。
- 用 `setExtensionPrompt` 注入，并由 `generate_interceptor` 做时序兜底。
- 注入中会宣告状态机为唯一状态权威，不再输出 INDRS、abstract、note 或 GM_STATE等第二套状态。
- Phantasm 的世界运作逻辑已全部内置到 Planner、结算器、状态结构和模块提示词中，没有需要另行导入的配置或可选模式。
- 正文生成后独立结算，区分“Planner 打算发生”和“正文实际发生”。
- 状态随聊天保存在 `chatMetadata.worldStateMachine`，不同聊天互不污染。
- 所有区块都以简单中文显示和编辑；插件保存时自动转换为内部 JSON。删除完整段落即可删除对应项目，`lockedPaths` 可锁字段。
- 自动保留最近 10 个正文生成或手动整理前的状态检查点；界面只回滚上一轮状态版本。
- 可触发事件是有既存来源的条件状态，不是逐轮刷新的选项池：仍可能成立时保留稳定ID，触发、明确过期或条件已不可能时才移除；允许为0，不为凑数制造事故或巧合。全部状态栏目仍会合并重复、清理无价值终态并执行本地生命周期压缩。
- Planner 和事实结算的全局总规则均可编辑；世界硬规则、世界、人物、NPC轨迹、关系、知识、任务、事件、触发器、线程、剧情推进、进程、因果、时间线和后台判断也各有独立可编辑提示词。
- 设置页按“API、注入模块、内置提示词、上一轮回滚”分类；注入模块以复选列表呈现，每个状态模块都能单独控制是否进入正文模型。
- 主面板按“场景地图、世界、人物、事务、世界书注入、系统”使用一级导航。“场景地图”是独立单面板栏目，点击后直接占满内容区，不再嵌套在“世界”的二级列表中；任务等事务仍保留原有分组。
- 主面板分类栏、移动端栏目栏、设置标签栏和顶部操作栏支持手指横向拖动；桌面鼠标滚轮位于横栏上时会转换为横向滚动，切换栏目后当前选项会自动滚进可视区域。
- 共享骰池默认关闭；启用后每轮只生成一个共享随机种和 1–3 枚顺序骰，供全部存在真实不确定性的模块共用。它不决定剧情是否推进，也不修改剧情节奏。
- 默认使用游戏式状态卡、人物卡、多轴关系卡、时间线和可展开详情；内部英文枚举与技术ID会自动翻译、解析或隐藏。
- 点击“编辑当前栏目”才进入中文编辑模式，展示层变化不会改变内部状态协议与注入结构。

## 安装

### 通过 GitHub 链接安装（推荐）

1. 在 GitHub 新建一个仓库，将本文件夹内的所有内容上传到仓库根目录。`manifest.json` 必须直接位于仓库顶层，不要在外面再套一层文件夹。必须连同 `src/` 和 `styles/` 两个完整文件夹一起上传，只上传顶层文件会导致插件安装后无法启动。
2. 在 SillyTavern 打开“扩展 → 安装第三方扩展”。
3. 粘贴 GitHub 仓库链接，例如 `https://github.com/<你的用户名>/zhizhi-state-machine`，然后点击安装。
4. 刷新 SillyTavern，从“魔法棒 → 芝芝状态机系统”打开。

扩展已开启 Git 自动更新标记；以后将新版本推送到同一仓库后，SillyTavern 可按其第三方扩展更新机制拉取更新。

### 不安装先看界面

直接双击 `preview.html`。它使用内置模拟数据，不需要启动 SillyTavern，也不会调用真实 API。你可以切换所有栏目、修改中文状态、查看 Prompt 编辑器和上一轮回滚。关闭大面板后，可用右下角的 `WORLD` 按钮重新打开。

完整的Mock API与逐项测试流程见 [`TESTING.md`](TESTING.md)。

### 安装到 SillyTavern

当前版 SillyTavern 可以按用户安装，也可以安装给所有用户。手动安装时，把整个 `zhizhi-state-machine` 文件夹复制到扩展目录：

```text
SillyTavern/data/<用户名称>/extensions/world-state-machine
```

如果选择“为所有用户安装”，则使用：

```text
SillyTavern/public/scripts/extensions/third-party/world-state-machine
```

重启或刷新 SillyTavern，在扩展管理器中启用“芝芝状态机系统”。它会出现在“魔法棒 → 芝芝状态机系统”，页面右下角也保留 `WORLD` 快捷按钮。

所有 Phantasm 相关规则均由本扩展提供，无需额外导入任何配置文件。

也可以把本目录作为单独 Git 仓库，然后在 SillyTavern 的“安装第三方扩展”中填写仓库地址。

## Planner API 配置

打开 `魔法棒 → 芝芝状态机系统 → 设置 → API`。默认勾选“使用酒馆默认 API”，状态机会直接跟随酒馆主界面当前连接和模型，不需要重复填写地址、模型或 Key；这类请求只包含状态机自己的系统消息和任务数据，不会自动夹带角色卡或聊天历史。

“单次输出 Tokens”只控制 Planner 一次返回的 JSON 长度。过大的输出预算可能让上游长时间预留生成资源甚至超时，因此内部最高使用 16384；超长历史先确定性本地合并，再通过接近资料请求上限且有边界重叠的有界大块完整覆盖，每块独立保存结果，不做等距抽样或最终大摘要。

如果取消该选项，则可填写一个 OpenAI Chat Completions 兼容接口：

- 可新建多个 API 配置档；每个配置独立保存名称、地址、API Key 和模型，点击配置名称即可立即切换。
- “自动拉取模型”会使用当前配置请求标准的 `/models` 接口，并将返回模型加入模型输入框的候选列表。
- “测试当前配置”会强制测试当前自定义 API，即使“使用酒馆默认 API”仍处于勾选状态也不会测错线路。
- API 地址既可以填 `https://host/v1`，也可填写完整的 `.../chat/completions`。
- 模型名按服务商要求填写。
- API Key 保存在 SillyTavern 的扩展设置中。它会存在浏览器端，请只在可信设备上使用。
- Planner 必须能稳定输出 JSON。建议使用擅长结构化输出、上下文足够长的模型，温度保持在 `0–0.3`。

浏览器会直接请求该地址，因此服务端必须允许 SillyTavern 页面的 CORS。若接口不允许浏览器跨域，需要自行使用带 CORS 的反向代理。

“破限提示词”是可选的自定义附加系统指令，留空时不会添加。填写后会随 Planner、事实结算和世界书拆解等状态机 API 请求发送；不要在其中写入 API Key 等敏感信息。

界面字体默认跟随酒馆，并以 `90%` 显示。可在同一设置页取消“字体跟随酒馆”，填写自定义字体；字体大小可在 `60%–140%` 之间调整。调整只改变文字大小，不会缩小面板或按钮点击区域。

## 使用顺序

1. 进入角色聊天，启用需要的世界书。
2. 插件不会在打开、启动或切换聊天时自动读取。请打开 `WORLD`，点击“读取并初始化”手动读取角色卡、Persona、世界书和完整聊天并建立状态。
3. 初始化后，“读取当前聊天”用于主动刷新；读取期间该按钮变为“终止读取”。“重新读取 / 重建”会本地扫描角色卡、Persona、完整历史（包括隐藏归档楼层）和已启用世界书，再以“全量提取→独立推演”两次请求建立基准快照。第一次没有逐栏完整返回就终止并保留旧状态，不追加第三次请求。
4. 检查人物、知识、事件与长期线程是否合理，必要时直接修改中文状态并保存。
5. 正常发送消息。生成前扩展在本地生成短状态注入，不调用 Planner API；正文完成后最多调用一次 API 统一结算。
6. 正文结束后等待事实结算完成。面板中的 `REV` 会再次增加。

顶部操作栏固定为“读取当前聊天｜清空读取｜整理状态｜设置｜回滚上一轮”。“清空读取”会清除当前聊天的全部状态机状态、读取证据缓存和回滚版本，但不会删除聊天消息、角色卡、Persona或原始世界书；清空后再次读取会从零建立全新状态。

没有配置 API 时扩展不会阻止正文生成，只会根据现有状态注入一个保守的本地降级提示。

如果在设置中启用“Planner失败时严格阻止正文生成”，未配置API、超时、响应结构错误等 Planner 失败都会中止本轮，不会继续使用旧状态生成正文。默认仍为关闭，便于无API的预览和降级使用。

### 控制注入模块

打开 `设置 → 注入模块`。关闭某个模块后：

- Planner仍会维护该模块的状态。
- 面板仍可查看和编辑该模块。
- 该模块不会出现在发送给正文模型的 `<WORLD_STATE>` 中。

每个模块使用内置规则告诉正文模型如何使用该类信息。默认关闭“知识与秘密、长期线程”，避免不必要的信息泄露或强制推进；只有已经形成、仍在生效且与本轮相关的因果影响才会进入正文。
“内置提示词”中的可编辑模块规则会同时发送给 Planner、结算器和正文模型；正文侧只收到已勾选且本轮非空模块的规则。

当多个已勾选模块同时超过“注入最大字符”时，插件会在所有非空模块之间公平分配空间，保留每个模块的标题和内容摘要，而不是丢弃排在后面的模块。被截短的模块会显示“本模块已按预算压缩”。如果设置的字符上限连所有已勾选模块的最小摘要都无法容纳，插件会仅超出必要的最小幅度，以保证勾选语义不失效。

状态模块通过酒馆原生扩展提示词接口按重要性分别注入深度 0–4；拆解后的世界书规则沿用原世界书条目的深度。关闭“启用自动状态机”会立即清空全部已注册提示词；切换聊天或修改模块设置时会使用固定 Prompt ID 覆盖为当前聊天的最新状态，不会保留上一份状态。

可在 `系统 → 最终注入` 核对上述所有实际注入文本。这里不是额外的一份注入，而是各深度状态提示与本轮世界书规则的合并预览；修改它会整体替换下一次生成的注入，避免原内容重复发送。修改设置会取消尚未使用的临时覆盖并立即按最新勾选项重新生成预览。

“环境与路人反应”只控制本轮的场所反馈和一次性旁观者反应。它不会让 Planner 凭空制造重要人物，也不会强制每轮都有人围观；关闭后，状态机不再向正文模型建议这类外部反应。

### 剧情推进、剧情节奏与共享骰池

“剧情推进”是常驻的当前状态，只保存这一段剧情正在向哪里移动、已经形成什么变化，以及进入下一阶段仍需什么。方向变化时覆盖旧版本，不保存流水；它不预写结果，也必须停在用户决策点。“长期线程”记录长期悬而未决的问题，“剧情推进”记录当前段落的移动方向。

“剧情节奏”是可选速度限制，默认关闭；它只约束正文模型每轮最多推进多少。“共享骰池”也是独立可选项，默认关闭；它只在多个结果都合理、确有不确定性且没有唯一答案时提供统一随机倾向。三者互不替代。

启用共享骰池后，每轮数字由插件在本地预先生成，所有模块共用一个 1–3 枚的顺序骰池，模型不能自选、跳过或重掷。可用于不确定行动、满足基础条件后的可触发事件、NPC多种合理日程、自然世界事件、世界进程幅度和已具备条件的长期线程方向。明确行程、唯一结果和完整因果链不掷骰；关系、知识、世界状态、时间线与因果影响不能被直接随机改变。行动检定规则为：1 大失败，2–10 失败，11–19 成功，20 大成功。

### 状态卡玩家意图

状态卡不会把模块原文直接发送给正文AI。当前任务、可触发事件、长期线程、人物概况和正在发生的世界事件提供“关注、介入、询问/调查”强交互；NPC活动轨迹、人物关系、世界进程、因果影响、时间线和玩家已经确认的知识只提供受限查询型交互。世界状态、剧情推进、玩家自身人物卡以及玩家尚未知晓的知识保持只读。

“关注”会把对应记忆提高为HOT并发送关注意图；“介入”只表示玩家尝试进入相关内容，不会直接触发事件、完成任务或改变世界；“询问/调查”受人物知识、距离、权限、现实手段和世界规则限制。NPC活动按钮只发送“尝试了解某人去向”，不会发送后台轨迹；未知秘密不会生成按钮。最终结果仍由正文和事实结算决定。

### 拆解世界书

打开 `设置 → 拆解世界书`：

1. 勾选“启用拆解世界书”。
2. 使用酒馆风格的多选下拉菜单选择整本世界书。候选只包含酒馆当前全局启用、当前角色主绑定/附加绑定和角色卡内嵌世界书；仅在编辑器中打开过的旧书不会出现。可同时选择多本，取消后该书会立即从读取、路由和注入中移除。每个条目的“纳入编译”与酒馆原条目的启用状态独立：禁用条目可以预编译和审计，但只有酒馆当前启用的条目会参与运行时投影。
3. 设置每轮精简字数和用于匹配的最近正文条数，保存设置。
4. 可点击“立即拆解已勾选条目”用唯一一次 API 建立缓存；若未手动拆解，正文生成时只建立本地原文规则缓存，不额外调用拆解 API。

打开 SillyTavern 自带的世界书编辑器并在世界书下拉框中选中一本当前已启用或已绑定的书后，旁边会出现“芝芝：一键拆解本书”。它只选择并拆解当前这一本书的启用条目，并取消之前选择的其他世界书；仅在编辑器中打开但未启用/绑定的书会被拒绝。需要同时使用多本时，在插件设置页的下拉菜单中多选。

已勾选条目的原文只在用户手动拆解时发送给拆解 API，整次操作最多一次请求；超过安全分类预算时不发送截断版本，直接使用本地无损事实目录。Planner source 始终保留完整世界书原文，并附加其分类投影；插件不会修改或删除来源。正文生成拦截时只从酒馆已经组装好的临时请求中抑制所选原文的原生重复，再由统一汇编器按 `factId` 投递一次。未勾选条目保持酒馆原有行为。

“无法确认原文已安全处理时阻止正文请求”是固定安全规则，不能关闭。如果已选世界书后来无法读取，插件会阻止该次正文生成，避免原文绕过拆解直接发送。世界书必须全局启用、绑定当前角色或内嵌于角色卡，才会出现在下拉菜单中。

## 锁定字段

在“世界状态”页编辑 `lockedPaths`。路径使用点号；数组使用下标。例如：

```json
{
  "world": { "time": { "display": "周一 14:30" } },
  "lockedPaths": [
    "world.time.timezone",
    "characters.0.identity",
    "events.2.status"
  ]
}
```

每次 API 返回后，本地代码都会从旧状态恢复这些路径，因此锁定不依赖模型遵守 Prompt。数组重排会改变下标；需要长期锁定时，建议不要让 AI 重排对应数组。

## 外置 API 协议

扩展向兼容接口发送普通 `messages`。用户消息是 JSON，`phase` 有四个值：

- `INITIALIZE_WORLD`：首次或手动重建。
- `REFRESH_WORLD`：旧版状态升级后，保留既有事实并从完整设定补齐相关NPC。
- `PRE_GENERATION_PLAN`：正文前推进与规划。
- `POST_GENERATION_RECONCILE`：正文后的事实结算。

正文前期望返回：

```json
{
  "state": { "schemaVersion": 21, "initialized": true },
  "plan": {
    "timeAdvanceMinutes": 5,
    "sceneAssessment": { "status": "quiet", "shouldAdvance": false, "intensity": "none", "evidence": ["当前交流仍在自然延续"] },
    "actorDecisions": [{ "characterId": "char", "action": "继续当前交流", "allowed": true, "reason": "人物在场且具备动机与机会" }],
    "backgroundQueue": [{ "sourceType": "task", "sourceId": "task-1", "decision": "carry", "reason": "尚未到期" }],
    "advanceDecision": { "mode": "continue", "sourceRefs": ["char"], "actorId": "char", "intensity": "none", "direction": "继续当前交流", "reason": "无需制造额外事件" },
    "npcUpdates": [],
    "triggeredEventIds": [],
    "eligibleDevelopments": [],
    "forbiddenDevelopments": [],
    "notes": ""
  },
  "injection": "<WORLD_STATE>\n时间：下午14:30\n本轮：可以继续当前交流\n</WORLD_STATE>"

```

正文后期望返回：

```json
{
  "state": { "schemaVersion": 21, "initialized": true },
  "actualChanges": ["两人结束了当前谈话"],
```

返回必须是严格 JSON。扩展会兼容外层 Markdown JSON 代码块，但不建议依赖这一点。

## 状态结构

顶层区块包括：

- `world`：时间、地点、环境与世界事实。
- `worldRules`：带适用范围、完整条件/例外、冲突优先级和来源引用的硬规则层。
- `characters`：人物维护等级、身份、别名、所属/权限/知识引用、动机、当前目标、日程、可用性、位置、持续状态与重要物品。
- `relationships`：并存关系、动态模式、双方视角、矛盾、依恋、伤害、边界、和解条件与分场景表现。
- `npcActivities`：核心人物和活跃NPC当前的移动过程、活动地点、实际行动与当前作用，每人一条当前过程快照；最终落点归人物概况。
- `map`：世界书静态全图、动态地点覆盖、当前位置以及带耗时/危险/权限引用的路线；界面区分全部与玩家已知视图。
- `knowledge`：信息的L1/L2/L3重要等级、独立公开状态、各角色认知、明确来源与可靠性。
- `tasks`：当前任务、负责人、任务/地点/人物/规则/知识/资源引用、完成条件、已核验条件、截止时间和状态；条件未逐项覆盖时程序拒绝 `done`。
- `events`：正在发生或已经发生的重要事件节点，以及节点的直接结果。
- `triggers`：条件满足后才可触发的事件。
- `threads`：长期剧情或事务线程。
- `processes`：仍在持续演变的世界级变化线及其驱动、停滞、衰减和结束条件。
- `causalEffects`：既存事件或事实留下的持续后果；状态区分正在形成、仍在生效、已解决或路径不成立。
- `timeline`：已结算事实时间线。
- `planner`：本轮计划、短注入和错误。
- `lockedPaths`：人工锁定路径。

## 已知边界

- SillyTavern 的世界书选择来源在不同版本中有差异。扩展会合并全局选择、角色绑定、聊天绑定和角色卡内嵌世界书；初始化后应在 Planner 请求或状态中确认实际读取结果。
- 浏览器直连第三方 API 受 CORS 限制。
- 回滚只恢复上一轮正文生成或手动整理前的世界状态，不会删除或恢复 SillyTavern 聊天消息，也不会修改原始世界书。后台最多保留最近 10 轮；这些检查点不会发送给 AI，正文注入只使用当前最新状态。
- 面板使用中文文本编辑；复杂嵌套、稳定ID和状态合并仍由插件内部 JSON 负责。
- 世界当前时间是唯一通用时钟。活动、事件、进程、因果与时间线不再各自维护更新时间；任务截止时间等确实影响行动的硬条件仍会保留。
- 时间线只作为用户可见的审计记录保存在面板中，不属于任何正文注入模块；最终注入不会读取或输出时间线。

## 安全与因果保证

真正的边界不只写在 Prompt 中：锁定字段由本地合并强制执行；正文后的唯一一次状态机调用以实际助手消息为结算依据；调用计数锁会阻止同一操作超过额度上限。API 失败时保留旧状态，不重试，也不会把半截输出写入状态。
