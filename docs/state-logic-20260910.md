AI继续返回原有JSONL差量，字符串中少量明确标签可被代码解析。解析结果保存在聊天runtime中，原始状态仍为句子。计算结果与相应原文一起进入正文注入，不只留在面板。本轮planner结论也进入正文，但明确标注为AI判断，不得覆盖事实、例外或本地受阻判断。

句子模式移除每栏最多5条与总字符预算两处跳过逻辑。相关状态完整回传，不按长度切割；地图在相关时回传，历史在回顾时召回。仍尊重用户手动关闭的注入模块及自定义最终注入覆盖。独立世界书编译器和旧结构模式的预算不在此次修改范围。

## 时钟与日程

- 公历日期及24小时时分；年号形式如“昭国四年秋第十七日”，支持中文数字和阿拉伯数字。
- 年号时钟仅在同年同季比较，不臆造阴历、每季长度或年号与公历的映射。跨年跨季未提供历法时标记待核实。
- “三日后”等以首次建立时的剧情时间锚定；可显式写`锚定：昭国四年秋第十七日`，用于从较晚正文读取早先约定。旧档无锚点的相对日程不擅用当前日期；已有旧版公历缓存延续。
- 相同正文、无变化保存、用before修改其他标签，不移动已锚定日期。真正改期应改`时间`为新的明确日期。
- 日期与时辰精度分开：当日到期但时辰未定不会自动算作完成；超期事项继续保留。临时有效期只有日期时，当日结束后才过期。

## 权限、资源与条件

示例仅表示格式，不是写入用户剧情的事实：

```text
夏寻樨｜允许：书房、小院｜禁止：出院门｜解除条件：事实(禁足已经解除)
夏寻樨｜资源：银两｜持有：5
递信｜玩家接受：是｜前置条件：资源(夏寻樨/银两)>=3 && 位置(守卫)=院门
守门事件｜实施者：守卫｜准备条件：状态(准备)=已完成｜到场条件：位置(守卫)=院门｜时间条件：昭国四年秋第20日
路线：书房 → 小院｜开放：是｜耗时分钟：5
```

条件解析支持`位置(人物)`、`资源(人物/资源名)`、`状态(事项)`的明确比较，以及`事实(逐字原文)`。` && `表示全部，` || `表示任一，AND优先。只认明确事实；矛盾值、推测、单位不明或不支持的自然语言条件均待核实。代码不执行文本，也不把缺少信息当作通过。

触发器逐项检查实施者、准备、到场与最早时间，缺项不能宣称可触发；满足也只具备候选资格，不自动发生。资源检查只是可用量校验，不因提出行动而扣减。路线只使用已确认开放的边及其方向，缺图不判定不连通；移动时长检查不等于已经到达。

权限按明确主体与允许/禁止标签检查；解除条件必须被确认为满足。有例外时留给AI核实，不直接解除。主观情感不会被解析成物理禁令。自由输入中的任意行动意图仍由AI提取，代码仅能判断已经明确表达的行动。

## 玩家与场外NPC

提示词要求玩家明确接受才进入主角任务，NPC目标归人物或势力；旧任务未带接受证据时，回传明确提醒任务归属待核实，不能代为承诺。已有自由文本的错归属由下一次读取的同一个请求修正，不在安装时凭关键词改写剧情。

逐人检查场外位置、职责、准备、资源、经过的剧情时间与知识传播渠道。已存在栏目也必须复查，场外推演保留推测标记。当前剧情节奏和本地时钟传入既有的一次更新请求，禁止无时间依据地完成旅行或大型活动。v0.16.71已恢复全栏目必填：先读取原始世界书与上下文，再按已有设定推演缺项；不得留空或使用暂无/未知占位，清理后有空栏即未完成。

## 生命周期及历史

已明确完成、取消、结束、失效、撤销的临时事务退出活跃列表；一次性且已触发的触发器消耗。临时权限/效果按明确期限或解除条件清理。日程到期不会完成，规则、身份、秘密、未兑现承诺不会按热度或时间删除。锁定栏目不会被自动清理。

新完整人物/活动快照在主体精确相同、覆盖旧标签且只有一个无歧义新版本时替换旧快照；部分记录和冲突信息不自动删除。语义合并仍交给AI差量或智能整理。

原文保存在`runtime.sentenceArchive`，时间线界面可见；不会把历史全量再发给更新模型。已结束结果先回传正文一次，成功结算才记投递，之后静默；明确回顾可召回，已完成任务也能供依赖检查。持续影响应保留在活跃状态/事实锚点，不仅放历史。归档去重，空保存不增长；本地历史随真实变化增长，正文不重复堆叠历史。回滚与聊天隔离包含时钟、归档和投递回执。
