# 芝芝状态机系统（SillyTavern 扩展）

这是一个把“世界模拟”和“正文写作”分开的 SillyTavern 前端扩展。Planner API 维护持久世界状态并给出本轮约束；它既可直接跟随酒馆当前 API，也可使用单独的 OpenAI 兼容接口。正文完成后，Planner 再进行一次事实结算，只有真正写进正文的事情才成为历史。

## 当前实现

- 读取当前角色卡、Persona、聊天以及能够从 SillyTavern 上下文解析到的已启用世界书。
- Planner 直接读取酒馆当前可见的 user/assistant 正文，酒馆已隐藏（`is_system=true`）的楼层不会读取。手动读取、初始化或重建会读取全部可见聊天；自动普通轮次按“最近正文条数”读取，设为 `0` 时代表全部可见正文。
- 所有计费模型调用都有本地硬上限：普通正文生成前只做本地规划，正文完成后最多 1 次 API 检查全部模块但只返回实际变化的增量；读取/初始化或重建最多 2 次；手动世界书拆解最多 1 次。达到上限后代码会阻止额外请求，失败不会自动重试扣费。
- GPT-5 / o 系列会自动使用兼容的输出参数与低推理强度。受调用上限保护的请求只尝试一次结构化 JSON；若上游超时、返回空内容或无效 JSON，会保留旧状态并显示错误，不再切换模式追加第二次扣费。
- 初始化时面板会显示“读取资料 → 处理世界书 → 等待模型”三阶段进度、实际读取条数及失败详情；状态机面板不会再遮挡酒馆自带的确认或 API 错误弹窗。
- 读取/初始化时，资料不超过本地阈值便直接用一次请求完整读取并建立状态；资料较大时，本地把全部原文记录无遗漏地分成前后两半，第 1 次读取前半并输出证据，第 2 次读取后半、综合前半证据并建立完整状态。不会抽样、跳过或产生第三次请求；若任一半超过安全容量，会在调用 API 前明确失败。
- 自定义 Planner API 通过 SillyTavern 本机后端转发，不再从浏览器跨域直连供应商。大正文不会再因浏览器 CORS 直接报 `Failed to fetch`；后端转发失败也不会改走另一线路重试，因此仍遵守整次读取最多两次计费调用。
- 后端转发使用 SillyTavern 官方 `getRequestHeaders()` 取得当前 CSRF 令牌；“使用酒馆默认 API”开关切换后立即保存，关闭设置窗口时不会出现界面已勾选、实际仍走自定义 API 的状态错位。
- 世界书逐轮相关性筛选在本地完成，不消耗 API。超过 200 条时先按常驻标记、关键词和当前正文预筛，再对最多 200 条建立详细缓存，避免数千条世界书冻结界面；初始化仍会无遗漏覆盖下拉菜单中已选世界书。手动拆解会把已选世界书的启用条目压到一个请求内；返回缺项或失败的条目使用本地原文规则降级，不会拆批重试。
- 设置中的“分解正文”和“拆解世界书”是两个独立页面：前者控制普通轮次读取范围与两次调用上限，后者只管理世界书条目、缓存和本地逐轮路由。
- 正文注入不再共用单一深度：当前反馈与 Planner 位于深度 0，世界与人物快照位于 1，地图/关系/知识位于 2，任务/事件/因果位于 3，长期后台项目位于 4；拆解后的世界书规则沿用对应原条目的世界书深度。
- “系统 → 输入来源”显示最近一次推演真正读取到的世界书名称、启用条目数、正文条数、角色卡与 Persona 状态；发现但读取失败的世界书会单独列出。
- “系统 → 最终注入”以独立文本模块展示下一次真正发送给正文模型的全部状态与世界书规则；设置中未勾选的模块不会注入，也不会出现在这里。点击小铅笔可临时修改完整文本，保存后的覆盖只用于下一次生成，结算后自动恢复动态组合。
- 顶部“世界书注入”与“世界、人物、事务、系统”并列；每个已拆解条目对应一个独立文本模块。点击小铅笔可修改核心规则、触发情境、条件规则和必要背景，保存后下一轮会重新筛选并注入。
- “环境与路人反应”可在注入模块中单独开关。公共场景里由正文动作自然触发的轻量反应（如飞机乘客回头看一眼）可以出现，但临时路人不会被写进持久 NPC、关系或长期事件。
- 第一次运行建立完整状态；此后使用同一份状态增量演化，不逐轮重建。
- 每轮正文生成前只在本地读取最近一次已结算状态并生成短注入；正文完成后用唯一一次 Planner 请求检查全部栏目。无变化默认 `KEEP` 并省略，已有对象使用 `UPDATE/REPLACE/MERGE`，只有独立新对象才能 `CREATE`。
- 顶部提供“整理状态”：智能整理会在本地合并重复与旧版本、清除失效低价值项并压缩较早时间线；“清理临时信息”只移除非HOT的L1。两种操作都不调用AI、不修改原始世界书，整理前自动建立快照并生成新REV，可通过“回滚上一轮”恢复。
- 设置新增默认关闭的“剧情节奏”。关闭时完全沿用正文模型原本节奏；开启后可选极慢、慢速、中速或快速，并分别控制是否允许自动切场景、自动时间跳跃。它只限制每轮最大推进幅度，不规划剧情、不提高事件强度，任何档位都必须停在用户决策点。
- 本轮推进依次执行剧情压力与空转侦测、角色行动与因果判断、后台事件队列、推进调度，但不新增四个设置项：行动与因果规则并入“因果影响”，其余三项并入“本轮后台判断”。它们复用现有状态ID，不复制事件数据；允许平静延续，不用突发事件填补冷场。
- NPC差异化调度：在场人物实时微观更新；离场人物按一小时后台间隔进行宏观更新；未到期则保持原状态。
- 人物概况只保存“是谁、在哪里、当前重要处境、持续状态、重要物品”。持续状态和重要物品只保留当前版本，并随恢复、治疗、遗失、转交、损毁或失去剧情价值自然更新和删除。
- NPC分为核心人物、活跃NPC和按需生成的背景NPC，并可按持续作用自然升降级。每个持久NPC只保存一条当前活动快照；背景NPC不长期占用状态。
- 场景地图维护当前位置、已知地点和通行路线，阻断路线会约束人物移动，避免无过程瞬移。
- 人物关系只保存当前已成立的自然语言描述和依据，不使用亲密度、信任度、紧张度或百分比评分；两个方向的认知独立维护，不会自动对称或升级。
- 知识以L1普通、L2重要、L3核心表示保留优先级，并以保密、受限、公开另行表示传播状态；重要性与公开状态互不替代。
- 每条运行记忆同时维护 `priority` 与 `activity`：L1/L2/L3决定能否淘汰，HOT/WARM/COLD决定本轮是否需要调用。正文新建或实际更新的条目自动升为HOT；长期未命中会由本地程序自然衰减到WARM、COLD。
- 最终注入只使用HOT以及少量与当前人物、地点或任务直接相关的WARM。L3+COLD仍保存在状态或原始世界书中，但不会仅因重要而每轮塞给正文模型；再次被当前正文或世界书路由命中后才升温。
- 所有模块都允许为空。空表示当前没有值得进入运行态的信息；模型不得为了填满栏目制造NPC活动、任务、线程、事件或秘密，也不得用旧的模块文本填补空状态。
- 所有状态遵守单一主归属：现在能主动推进的是任务，等待条件的是可触发事件；一次条件节点是事件，长期未决故事是线程；围绕用户故事的是线程，世界自行变化的是进程；历史回顾进时间线，仍影响当前的重要节点进世界事件；当前结果进世界状态，来源与持续后果进因果影响；人物当前落点进概况，具体移动过程进NPC轨迹；怎么看对方进关系，知道什么进知识。其他模块只保留本模块结果或稳定ID引用，不重复全文。
- 每次保存执行本地 `STATE_GC`：删除无价值终态、覆盖同对象旧版本、按权威键合并重复、把重要完成节点归档到时间线、压缩久远历史，并保护L3核心信息。L1临时状态在长期未更新后自动消费，L2只在活跃期间维护。
- 世界书、角色卡和Persona继续作为长期设定权威且原文始终保留；初始化只做检索、分级、去重、提炼和当前化，不再把两万字压成一份固定摘要，也不把完整世界观、生平和组织介绍复制进 `world.facts`。
- 时间线具有分辨率衰减：近期节点保持具体，超出容量的较早L1/L2记录会按阶段合并成摘要，L3历史不因容量自动删除。
- 世界状态只记录“现在是什么样”的当前快照；世界事件保存“发生了什么”的重要节点；世界进程只维护仍在演变的家族、组织、战争、公司权力、政策、舆论或大型环境变化线。
- “因果影响”保存既存事件或事实留下且仍在生效的后果。影响形成前为 `developing`，形成并持续生效后为 `active`，真正消失后才移除。
- 升级旧版后会自动迁移旧提示词，并在下一轮保留既有事实、重新读取完整角色卡和世界书以补齐相关NPC；旧自定义提示词保存在 `promptMigrationBackup`。
- 用 `setExtensionPrompt` 注入，并由 `generate_interceptor` 做时序兜底。
- 注入中会宣告状态机为唯一状态权威，不再输出 INDRS、abstract、note 或 GM_STATE等第二套状态。
- Phantasm 的世界运作逻辑已全部内置到 Planner、结算器、状态结构和模块提示词中，没有需要另行导入的配置或可选模式。
- 正文生成后独立结算，区分“Planner 打算发生”和“正文实际发生”。
- 状态随聊天保存在 `chatMetadata.worldStateMachine`，不同聊天互不污染。
- 所有区块都以简单中文显示和编辑；插件保存时自动转换为内部 JSON。删除完整段落即可删除对应项目，`lockedPaths` 可锁字段。
- 自动保留最近 10 个正文生成或手动整理前的状态检查点；界面只回滚上一轮状态版本。
- 可触发事件采用逐轮候选池：每轮维持 4–8 条；若本轮没有候选实际触发，结算时淘汰旧候选并为下一轮换新。全部状态栏目会合并重复、删除已结束低价值项目并执行本地硬上限，防止状态与注入随聊天轮数持续膨胀。
- Planner 和事实结算的全局总规则均可编辑；世界、人物、NPC轨迹、关系、知识、任务、事件、触发器、线程、剧情推进、进程、因果、时间线和后台判断也各有独立可编辑提示词。
- 设置页按“API、注入模块、内置提示词、上一轮回滚”分类；注入模块以复选列表呈现，每个状态模块都能单独控制是否进入正文模型。
- 主面板按“场景地图、世界、人物、事务、世界书注入、系统”使用一级导航。“场景地图”是独立单面板栏目，点击后直接占满内容区，不再嵌套在“世界”的二级列表中；任务等事务仍保留原有分组。
- 主面板分类栏、移动端栏目栏、设置标签栏和顶部操作栏支持手指横向拖动；桌面鼠标滚轮位于横栏上时会转换为横向滚动，切换栏目后当前选项会自动滚进可视区域。
- 共享骰池默认关闭；启用后每轮只生成一个共享随机种和 1–3 枚顺序骰，供全部存在真实不确定性的模块共用。它不决定剧情是否推进，也不修改剧情节奏。
- 默认使用游戏式状态卡、人物卡、关系进度条、时间线和可展开详情；内部英文枚举与技术ID会自动翻译、解析或隐藏。
- 点击“编辑当前栏目”才进入中文编辑模式，展示层变化不会改变内部状态协议与注入结构。

## 安装

### 通过 GitHub 链接安装（推荐）

1. 在 GitHub 新建一个仓库，将本文件夹内的所有内容上传到仓库根目录。`manifest.json` 必须直接位于仓库顶层，不要在外面再套一层文件夹。必须连同 `src/` 和 `styles/` 两个完整文件夹一起上传，只上传顶层文件会导致插件安装后无法启动。
2. 在 SillyTavern 打开“扩展 → 安装第三方扩展”。
3. 粘贴 GitHub 仓库链接，例如 `https://github.com/<你的用户名>/zhizhi-state-machine`，然后点击安装。
4. 刷新 SillyTavern，从“魔法棒 → 芝芝状态机系统”打开。

扩展已开启 Git 自动更新标记；以后将新版本推送到同一仓库后，SillyTavern 可按其第三方扩展更新机制拉取更新。

### 不安装先看界面

直接双击 `preview.html`。它使用内置模拟数据，不需要启动 SillyTavern，也不会调用真实 API。你可以切换所有栏目、修改中文状态、查看 Prompt 编辑器和上一轮回滚。关闭大面板后，可用右下角的 `WORLD` 按钮重新打开。

完整的Mock API与逐项测试流程见 [`TESTING.md`](TESTING.md)。

### 安装到 SillyTavern

当前版 SillyTavern 可以按用户安装，也可以安装给所有用户。手动安装时，把整个 `zhizhi-state-machine` 文件夹复制到扩展目录：

```text
SillyTavern/data/<用户名称>/extensions/world-state-machine
```

如果选择“为所有用户安装”，则使用：

```text
SillyTavern/public/scripts/extensions/third-party/world-state-machine
```

重启或刷新 SillyTavern，在扩展管理器中启用“芝芝状态机系统”。它会出现在“魔法棒 → 芝芝状态机系统”，页面右下角也保留 `WORLD` 快捷按钮。

所有 Phantasm 相关规则均由本扩展提供，无需额外导入任何配置文件。

也可以把本目录作为单独 Git 仓库，然后在 SillyTavern 的“安装第三方扩展”中填写仓库地址。

## Planner API 配置

打开 `魔法棒 → 芝芝状态机系统 → 设置 → API`。默认勾选“使用酒馆默认 API”，状态机会直接跟随酒馆主界面当前连接和模型，不需要重复填写地址、模型或 Key；这类请求只包含状态机自己的系统消息和任务数据，不会自动夹带角色卡或聊天历史。

“单次输出 Tokens”只控制 Planner 一次返回的 JSON 长度。过大的输出预算可能让上游长时间预留生成资源甚至超时，因此内部最高使用 16384；超长输入通过本地等距取样控制，不会通过增加请求次数解决。

如果取消该选项，则可填写一个 OpenAI Chat Completions 兼容接口：

- 可新建多个 API 配置档；每个配置独立保存名称、地址、API Key 和模型，点击配置名称即可立即切换。
- “自动拉取模型”会使用当前配置请求标准的 `/models` 接口，并将返回模型加入模型输入框的候选列表。
- “测试当前配置”会强制测试当前自定义 API，即使“使用酒馆默认 API”仍处于勾选状态也不会测错线路。
- API 地址既可以填 `https://host/v1`，也可填写完整的 `.../chat/completions`。
- 模型名按服务商要求填写。
- API Key 保存在 SillyTavern 的扩展设置中。它会存在浏览器端，请只在可信设备上使用。
- Planner 必须能稳定输出 JSON。建议使用擅长结构化输出、上下文足够长的模型，温度保持在 `0–0.3`。

浏览器会直接请求该地址，因此服务端必须允许 SillyTavern 页面的 CORS。若接口不允许浏览器跨域，需要自行使用带 CORS 的反向代理。

“破限提示词”是可选的自定义附加系统指令，留空时不会添加。填写后会随 Planner、事实结算和世界书拆解等状态机 API 请求发送；不要在其中写入 API Key 等敏感信息。

界面字体默认跟随酒馆，并以 `90%` 显示。可在同一设置页取消“字体跟随酒馆”，填写自定义字体；字体大小可在 `60%–140%` 之间调整。调整只改变文字大小，不会缩小面板或按钮点击区域。

## 使用顺序

1. 进入角色聊天，启用需要的世界书。
2. 插件不会在打开、启动或切换聊天时自动读取。请打开 `WORLD`，点击“读取并初始化”手动读取角色卡、Persona、世界书和完整聊天并建立状态。
3. 初始化后，“读取当前聊天”用于主动刷新读取；读取期间该按钮变为“终止读取”。“重新读取 / 重建”会丢弃旧的 AI 状态与回滚快照，从角色卡、Persona、可见历史和已启用世界书重新建立，只有全部成功后才整体替换；终止或失败会保留原状态。
4. 检查人物、知识、事件与长期线程是否合理，必要时直接修改中文状态并保存。
5. 正常发送消息。生成前扩展在本地生成短状态注入，不调用 Planner API；正文完成后最多调用一次 API 统一结算。
6. 正文结束后等待事实结算完成。面板中的 `REV` 会再次增加。

顶部操作栏固定为“读取当前聊天｜清空读取｜整理状态｜设置｜回滚上一轮”。“清空读取”会清除当前聊天的全部状态机状态、读取证据缓存和回滚版本，但不会删除聊天消息、角色卡、Persona或原始世界书；清空后再次读取会从零建立全新状态。

没有配置 API 时扩展不会阻止正文生成，只会根据现有状态注入一个保守的本地降级提示。

如果在设置中启用“Planner失败时严格阻止正文生成”，未配置API、超时、响应结构错误等 Planner 失败都会中止本轮，不会继续使用旧状态生成正文。默认仍为关闭，便于无API的预览和降级使用。

### 控制注入模块

打开 `设置 → 注入模块`。关闭某个模块后：

- Planner仍会维护该模块的状态。
- 面板仍可查看和编辑该模块。
- 该模块不会出现在发送给正文模型的 `<WORLD_STATE>` 中。

每个模块使用内置规则告诉正文模型如何使用该类信息。默认关闭“知识与秘密、长期线程”，避免不必要的信息泄露或强制推进；只有已经形成、仍在生效且与本轮相关的因果影响才会进入正文。
“内置提示词”中的可编辑模块规则会同时发送给 Planner、结算器和正文模型；正文侧只收到已勾选且本轮非空模块的规则。

当多个已勾选模块同时超过“注入最大字符”时，插件会在所有非空模块之间公平分配空间，保留每个模块的标题和内容摘要，而不是丢弃排在后面的模块。被截短的模块会显示“本模块已按预算压缩”。如果设置的字符上限连所有已勾选模块的最小摘要都无法容纳，插件会仅超出必要的最小幅度，以保证勾选语义不失效。

状态模块通过酒馆原生扩展提示词接口按重要性分别注入深度 0–4；拆解后的世界书规则沿用原世界书条目的深度。关闭“启用自动状态机”会立即清空全部已注册提示词；切换聊天或修改模块设置时会使用固定 Prompt ID 覆盖为当前聊天的最新状态，不会保留上一份状态。

可在 `系统 → 最终注入` 核对上述所有实际注入文本。这里不是额外的一份注入，而是各深度状态提示与本轮世界书规则的合并预览；修改它会整体替换下一次生成的注入，避免原内容重复发送。修改设置会取消尚未使用的临时覆盖并立即按最新勾选项重新生成预览。

“环境与路人反应”只控制本轮的场所反馈和一次性旁观者反应。它不会让 Planner 凭空制造重要人物，也不会强制每轮都有人围观；关闭后，状态机不再向正文模型建议这类外部反应。

### 剧情推进、剧情节奏与共享骰池

“剧情推进”是常驻的当前状态，只保存这一段剧情正在向哪里移动、已经形成什么变化，以及进入下一阶段仍需什么。方向变化时覆盖旧版本，不保存流水；它不预写结果，也必须停在用户决策点。“长期线程”记录长期悬而未决的问题，“剧情推进”记录当前段落的移动方向。

“剧情节奏”是可选速度限制，默认关闭；它只约束正文模型每轮最多推进多少。“共享骰池”也是独立可选项，默认关闭；它只在多个结果都合理、确有不确定性且没有唯一答案时提供统一随机倾向。三者互不替代。

启用共享骰池后，每轮数字由插件在本地预先生成，所有模块共用一个 1–3 枚的顺序骰池，模型不能自选、跳过或重掷。可用于不确定行动、满足基础条件后的可触发事件、NPC多种合理日程、自然世界事件、世界进程幅度和已具备条件的长期线程方向。明确行程、唯一结果和完整因果链不掷骰；关系、知识、世界状态、时间线与因果影响不能被直接随机改变。行动检定规则为：1 大失败，2–10 失败，11–19 成功，20 大成功。

### 状态卡玩家意图

状态卡不会把模块原文直接发送给正文AI。当前任务、可触发事件、长期线程、人物概况和正在发生的世界事件提供“关注、介入、询问/调查”强交互；NPC活动轨迹、人物关系、世界进程、因果影响、时间线和玩家已经确认的知识只提供受限查询型交互。世界状态、剧情推进、玩家自身人物卡以及玩家尚未知晓的知识保持只读。

“关注”会把对应记忆提高为HOT并发送关注意图；“介入”只表示玩家尝试进入相关内容，不会直接触发事件、完成任务或改变世界；“询问/调查”受人物知识、距离、权限、现实手段和世界规则限制。NPC活动按钮只发送“尝试了解某人去向”，不会发送后台轨迹；未知秘密不会生成按钮。最终结果仍由正文和事实结算决定。

### 拆解世界书

打开 `设置 → 拆解世界书`：

1. 勾选“启用拆解世界书”。
2. 使用酒馆风格的多选下拉菜单选择整本世界书。候选只包含酒馆当前全局启用、当前角色主绑定/附加绑定和角色卡内嵌世界书；仅在编辑器中打开过的旧书不会出现。可同时选择多本，取消后该书会立即从读取、路由和注入中移除；书内只有酒馆已启用的条目参与处理。
3. 设置每轮精简字数和用于匹配的最近正文条数，保存设置。
4. 可点击“立即拆解已勾选条目”用唯一一次 API 建立缓存；若未手动拆解，正文生成时只建立本地原文规则缓存，不额外调用拆解 API。

打开 SillyTavern 自带的世界书编辑器并在世界书下拉框中选中一本当前已启用或已绑定的书后，旁边会出现“芝芝：一键拆解本书”。它只选择并拆解当前这一本书的启用条目，并取消之前选择的其他世界书；仅在编辑器中打开但未启用/绑定的书会被拒绝。需要同时使用多本时，在插件设置页的下拉菜单中多选。

已勾选条目的原文只在用户手动拆解时发送给拆解 API，整次操作最多一次请求。之后每轮根据酒馆实际正文在本地从缓存规则中选择相关内容。插件会在两个位置执行保护：构建 Planner source 时删除所选条目原文；正文生成拦截时再次从酒馆最终聊天请求中逐字剔除原文。未勾选条目保持酒馆原有行为。

“无法确认原文已安全处理时阻止正文请求”是固定安全规则，不能关闭。如果已选世界书后来无法读取，插件会阻止该次正文生成，避免原文绕过拆解直接发送。世界书必须全局启用、绑定当前角色或内嵌于角色卡，才会出现在下拉菜单中。

## 锁定字段

在“世界状态”页编辑 `lockedPaths`。路径使用点号；数组使用下标。例如：

```json
{
  "world": { "time": { "display": "周一 14:30" } },
  "lockedPaths": [
    "world.time.timezone",
    "characters.0.identity",
    "events.2.status"
  ]
}
```

每次 API 返回后，本地代码都会从旧状态恢复这些路径，因此锁定不依赖模型遵守 Prompt。数组重排会改变下标；需要长期锁定时，建议不要让 AI 重排对应数组。

## 外置 API 协议

扩展向兼容接口发送普通 `messages`。用户消息是 JSON，`phase` 有四个值：

- `INITIALIZE_WORLD`：首次或手动重建。
- `REFRESH_WORLD`：旧版状态升级后，保留既有事实并从完整设定补齐相关NPC。
- `PRE_GENERATION_PLAN`：正文前推进与规划。
- `POST_GENERATION_RECONCILE`：正文后的事实结算。

正文前期望返回：

```json
{
  "state": { "schemaVersion": 6, "initialized": true },
  "plan": {
    "timeAdvanceMinutes": 5,
    "sceneAssessment": { "status": "quiet", "shouldAdvance": false, "intensity": "none", "evidence": ["当前交流仍在自然延续"] },
    "actorDecisions": [{ "characterId": "char", "action": "继续当前交流", "allowed": true, "reason": "人物在场且具备动机与机会" }],
    "backgroundQueue": [{ "sourceType": "task", "sourceId": "task-1", "decision": "carry", "reason": "尚未到期" }],
    "advanceDecision": { "mode": "continue", "sourceRefs": ["char"], "actorId": "char", "intensity": "none", "direction": "继续当前交流", "reason": "无需制造额外事件" },
    "npcUpdates": [],
    "triggeredEventIds": [],
    "eligibleDevelopments": [],
    "forbiddenDevelopments": [],
```

正文后期望返回：

```json
{
  "state": { "schemaVersion": 6, "initialized": true },
```

## 状态结构

顶层区块包括：

- `world`：时间、地点、环境与世界事实。
- `characters`：人物维护等级、身份、位置、当前重要处境、持续状态与重要物品。
- `relationships`：有方向的关系状态及依据。
- `npcActivities`：核心人物和活跃NPC当前的移动过程、活动地点、实际行动与当前作用，每人一条当前过程快照；最终落点归人物概况。
- `map`：当前位置、已知地点、所属区域以及地点之间的路线状态。
- `knowledge`：信息的L1/L2/L3重要等级、独立公开状态、各角色认知、明确来源与可靠性。
- `tasks`：当前任务、负责人、依赖、截止时间和状态。
- `events`：正在发生或已经发生的重要事件节点，以及节点的直接结果。
- `triggers`：条件满足后才可触发的事件。
- `threads`：长期剧情或事务线程。
- `processes`：仍在持续演变的世界级变化线及其驱动、停滞、衰减和结束条件。
- `causalEffects`：既存事件或事实留下的持续后果；状态区分正在形成、仍在生效、已解决或路径不成立。
- `timeline`：已结算事实时间线。
- `planner`：本轮计划、短注入和错误。
- `lockedPaths`：人工锁定路径。

## 已知边界

- SillyTavern 的世界书选择来源在不同版本中有差异。扩展会合并全局选择、角色绑定、聊天绑定和角色卡内嵌世界书；初始化后应在 Planner 请求或状态中确认实际读取结果。
- 浏览器直连第三方 API 受 CORS 限制。
- 回滚只恢复上一轮正文生成或手动整理前的世界状态，不会删除或恢复 SillyTavern 聊天消息，也不会修改原始世界书。后台最多保留最近 10 轮；这些检查点不会发送给 AI，正文注入只使用当前最新状态。
- 面板使用中文文本编辑；复杂嵌套、稳定ID和状态合并仍由插件内部 JSON 负责。
- 世界当前时间是唯一通用时钟。活动、事件、进程、因果与时间线不再各自维护更新时间；任务截止时间等确实影响行动的硬条件仍会保留。
- 时间线只作为用户可见的审计记录保存在面板中，不属于任何正文注入模块；最终注入不会读取或输出时间线。

## 安全与因果保证

真正的边界不只写在 Prompt 中：锁定字段由本地合并强制执行；正文后的唯一一次状态机调用以实际助手消息为结算依据；调用计数锁会阻止同一操作超过额度上限。API 失败时保留旧状态，不重试，也不会把半截输出写入状态。
